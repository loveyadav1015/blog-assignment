Introduction

I am a first-year student of the CSAI branch at IIIT Lucknow. Before college, I thought programming was only about typing code. In my first weeks I learned that it is really about thinking. This blog is about my early journey with C++, how I try to solve problems, and what I plan to learn next.

How I Approach a New Problem

Whenever I see a new problem, my first instinct is to write the solution like a recipe: a list of ordered steps in plain English. Only after that do I turn each step into C++ code. My steps usually look like this:

  1. Read the problem twice and note the input and the output.
  2. Write the solution steps in plain English.
  3. Try the steps by hand on a small example.
  4. Convert each step into C++ code.
  5. Test with different inputs, especially tricky ones.

This habit saves me from staring at a blank screen, because one small step is always easier to code than a whole problem.

The Champion Idea

Finding the largest of three numbers

One problem that taught me a lot was finding the largest of three numbers. At first I compared every pair of numbers, and the code became messy. Then I learned the champion idea: keep one variable called largest, assume the first number is the champion, and let every other number challenge it. If a challenger is bigger, it becomes the new champion. 


#include <iostream>
using namespace std;

int main() {
    int a, b, c;
    cin >> a >> b >> c;

    int largest = a;
    if (b > largest) {
        largest = b;
    }
    if (c > largest) {
        largest = c;
    }

    cout << largest;
    return 0;
}

What I like about this idea is that it works for three numbers or three hundred. The logic stays the same and only the count changes.

Mistakes That Taught Me Something

I often forgot semicolons at the end of lines, and once I wrote a single equals sign inside an if condition instead of a double one. The program ran, but the answer was wrong. Now I read my conditions slowly, and I use the C++ reference website whenever I am unsure.
