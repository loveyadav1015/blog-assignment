Introduction

This week I solved a Codeforces-style problem called Traffic Light and got a wrong answer on a test I was sure I understood. The bug turned out to be one of the most common beginner mistakes: forgetting that a repeating sequence wraps around. In this post I walk through the problem, how I found the bug, and the fix, so you can avoid the same trap.

The problem

A traffic light repeats a string of colors such as rrrgyyygy, one letter per second. You can cross only on green (g). You know the current color, but not the exact second, so you need the longest wait that could happen from that color.

Debugging the wrong answer

What I expected

For the input 9 y with rrrgyyygy, I expected 3, because the three ys in the middle wait 3, 2 and 1 seconds. My program printed 3, but the correct answer is 4.

What I missed

There is another y at the very end. From there the light goes to the start of the string and walks through three reds before it reaches the green. That is a wait of 4 seconds. Since you do not know which y you are standing on, you must plan for the worst one.

Here is how I tracked it down:

  1. Write out every index of the string and mark each position that matches the current color.
  2. For each marked position, count the seconds until the next g.
  3. Check the last position separately, and see whether its wait crosses the end of the string.
  4. Take the maximum of all the waits, not the minimum.

The fix

The simplest trick is to double the string, so s becomes s + s. Then a wait that crosses the end simply continues into the second copy. Scan from right to left, remember the nearest g, and update the answer at each matching color. 

s += s;
int ans = 0, nextG = -1;
for (int i = 2 * n - 1; i >= 0; i--) {
    if (s[i] == 'g') nextG = i;
    else if (i < n && s[i] == c) ans = max(ans, nextG - i);
}
cout << ans << "\n";

A few things I learned from this bug:

  • Circular or repeating sequences almost always need a wrap-around check.
  • When you are unsure of your position, the answer is the worst case over all positions.
  • Test the first and last elements by hand before you submit.
  • A single linear pass is enough here, with no advanced algorithms needed.

Conclusion

The bug was not about syntax. My logic was correct for most of the string, but I forgot that the light never stops, and the end of the string connects back to the start. Writing the cases out in a table made the missing one obvious. Next time I meet a repeating pattern, the first thing I will ask is, "what happens at the edge?" That one question will save me many wrong answers.
